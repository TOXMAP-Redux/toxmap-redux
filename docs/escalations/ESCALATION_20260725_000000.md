## What Was Blocked

Story IDs **1.5.3** and **1.5.4** in the Phase 1 Epic 1.5 (Parquet Build Pipeline) have
completely different descriptions in two authoritative documents:

| Document | Story 1.5.3 | Story 1.5.4 |
|----------|-------------|-------------|
| `docs/product/TOXMAP_PROGRESS_TRACKER.md` (protected — source of truth) | Validate Parquet output against seed assertions | `manifest.json` schema + R2 upload |
| `agents/data-engineer/prompt.md` (pre-fix) | US basemap PMTiles download | `scripts/build_census_parquet.py` |

The work described is entirely different. The PROGRESS_TRACKER is the authoritative source of
truth per `AGENTS.md §1`. The DE agent would have implemented PMTiles download (tracker: Parquet
validation) and Census Parquet (tracker: manifest.json + R2), causing the Phase Manager to
report Phase 1 incomplete even after the DE agent considered its work done.

---

## Action Taken (Agent)

Per `AGENTS.md §8` ambiguity decision tree and `§12` escalation rules:

1. `agents/data-engineer/prompt.md` was updated to align with the PROGRESS_TRACKER:
   - 1.5.3 → "Validate Parquet output against seed assertions" (matches PROGRESS_TRACKER)
   - 1.5.4 → "`manifest.json` schema + R2 upload" (matches PROGRESS_TRACKER)

2. The work previously described under the old 1.5.3 and 1.5.4 (Census Parquet, PMTiles) was
   added to the DE prompt as new story IDs **1.5.5** and **1.5.6** with a note that they
   require a human RFC before the Phase Manager can track them.

3. This ESCALATION file was written. No PR is merged without human acknowledgment.

## Resolution (2026-07-25)

**Q1 — Add 1.5.5/1.5.6 to PROGRESS_TRACKER as Phase 1 stories?**  
No. Neither item is in Phase 1 DoD. No PROGRESS_TRACKER amendment needed for Phase 1.

**Q2 — Were Census Parquet and PMTiles originally Phase 1?**  
No. Correct phase assignments:
- **1.5.5 (Census Parquet):** Phase 7 prerequisite. DE implements `scripts/build_census_parquet.py`
  before FE dispatches `useDuckDBDemographics` (story 7.1.7). Phase 5 FE uses the BE API
  (dev mode), so the Parquet file is not needed until Phase 7 production validation.
- **1.5.6 (PMTiles basemap):** Phase 3 prerequisite, but not as a built pipeline. OPS performs
  a one-time manual `wrangler r2 object put` of the Protomaps pre-built US extract before
  Phase 3 FE is dispatched. Full pipeline automation (`scripts/build_pmtiles.py`) deferred
  to Phase 7.

**Q3 — Is manifest.json + R2 upload fully specified in ADR-004?**  
Yes. ADR-004 §GitHub Actions Workflow and §Parquet Build Pipeline specify the manifest schema,
R2 upload pattern, and the `epa_vintage_label` requirement. The DE agent has sufficient spec
to implement story 1.5.4.

- `docs/product/TOXMAP_PROGRESS_TRACKER.md` — Phase 3 prerequisites updated with PMTiles note;
  Phase 7 prerequisites updated with Census Parquet note
